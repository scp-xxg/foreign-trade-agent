# 成交准备度检查

执行前阅读[工具契约](references/contract.md)，字段详情见[输入Schema](references/schema.json)。调用`trade_buyer_research(action="closing-readiness", data=...)`，工具不可用时如实说明。

先明确企业成交口径，把企业批准规则映射为requirements，phase=readiness。逐项引用规则及实际证据；确认、待确认、冲突、不适用分别记录，必备条件不能因总分较高被绕过。不适用要有依据。补齐owner、due_at、依赖和追问；空清单工具返回needs_rules。结果为材料支持待审，不等于真实成交或可投产。

只返回内部待审材料，不自动发信、签署、认领收款、写CRM或启动履约。复用背调核验主体、谈单确认条件、沟通生成消息，不重复执行无关触达。来源引用仅说明原文关联，不能独立证明真实性。

## 验收与效果

关键缺项召回率=检出真实关键缺项/人工标注关键缺项；错误放行率=存在关键缺项却判可推进案例/判可推进案例。记录阻塞解决周期和同等材料检查耗时。重大阻塞错误放行验收为0。

用独立人工标注材料验证提取与状态，金额以人工核算对照；覆盖缺项、版本冲突、错误账户、未来记录、混合币种及不同付款方式。每项指标报告样本数、分子分母和观察周期，未测保持未知；业务改善需在可比客户和订单上观察，不把全部成交归因于技能。
