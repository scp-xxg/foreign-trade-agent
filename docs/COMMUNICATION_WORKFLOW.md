# 客户沟通工作流

对话框「客户沟通」是可关闭开关，与获客、客户背调互斥；按会话保留状态，普通发送和排队发送均携带工作流，显式命令不叠加。

输入：客户与渠道、沟通目标、往来原文及时间、已确认产品和供货事实及版本来源、实际发送历史及IANA时区。仅提供部分资料时先处理可完成阶段，集中询问关键缺项。

六技能：首次触达（trade-personalized-outreach）、回复分流（trade-reply-triage）、客户需求澄清（trade-needs-clarification）、有据答复（trade-grounded-reply）、跟进节奏（trade-followup-cadence）、沟通纪要与下一步（trade-communication-summary）。

无往来时走已审核线索的首次触达；有回复先分流，原跟进暂停，退订停止。需求缺项进入澄清，有问题进入有据答复；有实际发送记录及已知时区时规划跟进。各分支最后整理纪要，未触发阶段解释跳过原因。后续回复沿用前序资料重新分流。

输出：意图与阶段、需求缺口和追问、有来源的待审草稿、跟进建议、双方事项及未知负责人/期限、来源和各阶段状态。新增工具只做原文关联及规则检查，不自动检索事实、翻译、发送、保存CRM或创建定时任务。

效果：用独立人工标注对话评估缺项召回率、无效追问率、事实来源覆盖率、纪要事项召回率、草稿采纳率及审核耗时。虚构承诺、错误归属、退订后触达验收为零；没有实际送达数据不能计算回复转化率。
