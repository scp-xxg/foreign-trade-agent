# 对话中的外贸业务助手

插件显示名为“外贸业务助手（演示）”，版本 0.4.0，安装标识保持 foreign-trade-demo。使用支持原生工具调用的模型，可以在对话中处理业务；也可在聊天输入框输入 /，显式选择该插件。询盘、产品内容和协同工作台继续保留，对话和工作台使用当前账号的同一批记录。

多步业务建议在输入框的模型菜单选择“思考模式”，并配置支持原生工具调用的模型。若模型只返回操作说明或 JSON 示例，没有成功工具回执和对应状态卡，任务仍未执行；可要求继续实际执行或调整模型。系统不会把助手正文中的 JSON 自动当作工具执行。询盘状态与文件下载以真实回执和当前记录为准。

## 五个技能

| 技能 | 适合的请求 | 执行方式 |
|---|---|---|
| inquiry-quote | 即时查产品、核对 MOQ、计算模拟报价 | 原有 3 个本机 MCP 工具 |
| buyer-inquiry-followup | 核验买家、保存/修订询盘、准备回复、安排跟进 | 当前会话绑定的询盘与报价工具 |
| product-content | 导入资料与原图、确认事实、制作英文内容与图片资料包 | 当前会话绑定的产品内容工具 |
| cross-role-collaboration | 关联同订单资料、安排岗位任务、逐项人审、导出内部交接 | 当前会话绑定的协同工具 |

即时询价可以继续使用原流程。需要保存业务单和后续跟进时，助手会使用询盘记录流程，金额仍由相同的确定性报价引擎计算。

## 场景一：从公开资料到询盘与跟进

可以在新对话中输入：

> 请核验 LYRECO 的公开资料，公司注册国 FR，官网 https://www.lyreco.com/group/ 。请在我的账号保存一条团队构造的演示询盘：DESK-001，500 件，标准包装，交付目的国 Spain，生产时间未指定。请查产品、报价并生成待审中英文回复。该询盘不是 LYRECO 的真实订单，不要发邮件。

助手应返回可追溯的买家事实、询盘记录、工具计算的报价和未发送的回复草稿。官网自述、GLEIF 名称/国别匹配、未知关系分别标注；LEI 状态不作为信用评级，公开资料不证明采购意愿。

报价成功后，沿用聊天中的 PDF / Excel 下载卡。继续输入“把这条询盘改为 1000 件定制包装，重新报价并更新回复”，应读取最新记录、保存改动并重算。模拟小计从 USD 2400.00 改为 USD 5100.00，运费及税费仍未计入；历史报价保留，新草稿对应当前条件。

安排跟进时明确日期和时区，例如“明天上午 9 点，Asia/Shanghai，跟进包装设计要求”。助手先根据当前日期确定具体时间，不明时会询问。用户说“客户已经回复”后，当前询盘中未完成的跟进待办被取消。

跟进目前是站内待办和到期状态，不包含后台短信、邮件、桌面通知或自动催单。回复草稿不会自动发送。

## 场景二：上传资料与原图

1. 在聊天中上传当前产品的资料文件和原图，提出“请把这些文件整理成英文商品资料包”。
2. 助手优先使用附件导入工具，按本会话实际文件标识和简短元数据导入，展示产品事实、来源、图片署名和缺失条件；不会读取任意服务器路径或其他用户文件。
3. 用户核对摘要，明确回复“确认按这些事实生成”或提出修订。
4. 用户确认后，程序按候选索引精确采用原事实，不让模型重新编写长事实数组；随后单独调用生成工具，得到英文商品介绍、客服 FAQ 和实际可用的图片素材，资料卡提供下载。
5. 需要补充或修改时继续在聊天说明，也可以打开产品内容工作台编辑。修改后旧输出失效，重新确认并生成当前版本。

也可以输入：

> 请载入 Raspberry Pi 5 的真实公开资料示例，先展示规格、来源、照片许可和未知商务条件，等我确认后再生成。

此示例使用制造商规格及 SimonWaldherr 的 CC BY 4.0 照片。它没有具体 RAM 选型、批发价格、MOQ、库存、交期或经销授权信息。完整来源与许可见 [场景二来源说明](SCENARIO_TWO_SOURCES.md)。

目前图片功能是原图等比缩放、版式和文字排版，不是生成新的产品结构或 AI 场景图。翻译未通过时明确返回基础模板；非英文内容未完成翻译时不会冒充已生成英文图片。展示和下载仅依据实际工具回执，不由模型编造链接。

### 显式本地原文模板

生成模式默认仍为 `ai`。模型服务暂不可用，或用户明确希望本地整理时，可以在产品内容工作台选择“本地原文模板”，核对事实、原图与署名后生成。此模式**完全不调用生成模型、不翻译事实**，只把已确认的原文组织为商品说明、FAQ 和图片版式。要得到英文资料，用户须先确认产品名称、事实标签和值都已是英文；中文原文仍可形成原文模板，但英文图片暂停生成。

本地示例可上传 [product_facts_en.csv](../extensions/foreign_trade/demo_product/product_facts_en.csv) 和场景二的许可照片。该 CSV 将原有公开示例的 `label_en`、`value_en` 原样复制为导入列，保留来源 URL、核验日期与证据，没有新增产品事实。上传后仍需展示摘要并取得用户明确确认，不能因素材来自仓库就跳过确认。

聊天工具的参数示意如下，ID 与修订号均取实际最新回执：

```text
trade_product_content(
  action="generate",
  pack_id=PACK_ID,
  revision=LATEST_PACK_REVISION,
  confirmed=true,
  data={"generation_mode": "template"}
)
```

`generate` 的 `data` 只接受 `generation_mode`，值为 `ai` 或 `template`；确认标记和修订号仍在工具顶层。认证 HTTP 生成接口则在请求 body 中接收 `revision`、`confirmed` 和 `generation_mode`。生成模式不会绕过当前账号归属、事实确认、图片署名或版本冲突检查。

| 请求模式与结果 | 含义 |
|---|---|
| `generation_mode=ai`、`method=ai_grounded` | AI 翻译通过事实保持检查 |
| `generation_mode=ai`、`method=template` | AI 翻译失败或不合格后的原文回退，不能声称未尝试模型 |
| `generation_mode=template`、`method=template` | 用户显式选择本地原文模板，生成阶段不调用模型 |

显式模板回执、文案和 ZIP 来源说明均保留提示：“用户选择本地原文模板，未调用模型；需要英文结果须确认原始事实已为英文”。仅有 `method=template` 不足以区分主动本地模式与 AI 失败回退，应同时核对 `generation_mode`。

如果从聊天入口发起，聊天模型本身仍需正常完成工具编排。选择本地生成模式不能修复聊天模型的 HTTP 500；在该情况下可通过工作台继续完成同一业务记录。工作台完成不等于连续模型聊天验收通过。

## 场景三：跨岗位协同

请按 [跨岗位协同说明](SCENARIO_THREE.md) 从已有询盘建立协同单。岗位负责人是当前账号记录的业务标签；任务依赖、资料版本和人工验收由服务端核对。默认 DESK-001 模拟资料不会自动确认。来源变化后需复核相关任务，内部交接稿保留待确认项，不会自动发给客户或队员。

## 当前用户、确认和版本

- 八个原生工具是 trade_save_inquiry、trade_import_product、trade_confirm_product_facts、trade_inquiry、trade_calculate_quote、trade_product_content、trade_collaboration、trade_review。它们从已认证会话绑定用户，只在当前可见且已激活的插件中提供。
- 常见单 SKU 新建/改单优先使用扁平字段保存工具；附件导入与候选事实确认也使用显式字段工具。多 SKU 或复杂编辑保留通用入口。这降低长嵌套 JSON 的生成负担，不保证任何模型都能自动正确路由或一次完成多步操作。
- 不允许模型传 owner_user_id，不从提示词、邮箱或公司名称判断账号归属。
- 所有已存在业务记录的写入使用工具返回的当前 revision；冲突先重新读取，避免覆盖另一个页面的更新。
- 原生业务工具拒绝损坏或重复键 JSON，不使用框架的宽松 JSON 修复结果写入记录；本轮未读取对应技能时，工具返回技能路径并阻止业务写入。
- 已启用这些原生业务工具的模型请求使用完整响应方式接收参数，以兼容部分网关流式工具参数拆分异常。它只改变该请求的传输方式，不修改模型服务配置；其他请求保持原有流式设置。
- 聊天询盘状态卡根据保存回执显示核验、草稿和跟进状态；展开时读取当前账号的当前版本，不把模型口头总结作为完成证据。
- 产品资料由建议到生成必须经过用户看到事实摘要后的明确确认。用户未回复不视为确认。
- 聊天引用的文件仍须经过当前账号归属和本会话附件校验。未导入成功不能声称已读取内容。
- 工作台是查看、纠错和继续编辑的辅助入口。模型工具暂不可用时可继续使用工作台，不绕过认证去访问数据库。
- 系统不向买家发消息、不发布电商商品、不下单或付款。

## 队友升级安装

首次部署按 [队友部署指南](TEAM_SETUP.md) 完成 setup、init、start。已有实例先停止自己运行的网页后端和 MCP，保存本地代码改动，再执行：

~~~bash
git pull --ff-only
python3.11 extensions/foreign_trade/team.py setup
.venv/bin/python extensions/foreign_trade/team.py install --username YOUR_USERNAME
.venv/bin/python extensions/foreign_trade/team.py start
~~~

默认数据目录为 ~/.foreign-trade-agent。自定义目录时，在 install 和 start 中均传入相同的 --app-home /your/data/directory。不用新建账号、复制开发者数据库或删除原来的业务记录。

虚拟环境和 SQLite 版本须满足 [部署指南](TEAM_SETUP.md) 的当前要求；旧环境不能仅因 Python 命令可执行就直接用于升级。升级保留私有恢复快照，遇到迁移拒绝应保留现场并按明确诊断处理，不跳过版本或覆盖数据库。

install 会原位更新 foreign-trade-demo，为所选账号安装五个技能，使用显示名“外贸业务助手（演示）”；老的 inquiry-quote 和 3 个报价 MCP 工具保留。其他账号应分别执行安装。团队入口同时应用公开项目的首页和默认提示词；如有自行编辑的配置，升级前保留自己的版本。新的提示词版本标识为带内容摘要的 foreign-trade-demo-v4-*，旧版本仍可在提示词管理中核对。

新增原生工具代码需要重启这个公开项目后端。只有插件说明内容变化时，可在运行中的页面关闭再开启插件刷新缓存。随后新建聊天验收；旧会话中历史文本不会被改写。

## ZIP 的宿主依赖

~~~bash
.venv/bin/python extensions/foreign_trade/manage.py build
~~~

生成 extensions/foreign_trade/dist/foreign-trade-demo.zip，包含四份技能、插件声明、宿主要求、本文和原有报价 MCP 运行源码。八个原生业务工具需要配套宿主；原有三个目录 MCP 工具单独计数。

**0.4.0 的完整三场景能力依赖本公开分支。** ZIP 自身不会把询盘数据库服务、附件权限校验、原生工具适配器和前端资料卡安装到任意未修改的上游 HugAgentOS。队友应更新整个公开仓库。ZIP 适合在已具备配套代码的实例中导入或更新技能；旧的独立 MCP 仍仅提供三个公开模拟查询/计算工具。

原生工具的说明放在清单扩展元数据中，不写成 9120 端口上的 MCP 工具。不要为兼容导入而把账号 ID、会话 Cookie、数据库凭据或密钥嵌入插件包。

## 验收清单

本轮结果见 [2026-10-28 验收记录](ACCEPTANCE_20261028.md)：三场景的工作台 UI 和本地资料/交接流程已验证，本地与原生工具测试已通过；真实模型聊天因 HTTP 500 未通过。此前记录保留在 [2026-10-21 验收记录](CHAT_PLUGIN_ACCEPTANCE.md)，不作为本轮结果。

以下是模型服务恢复后仍需重新执行的聊天验收目标，不是本轮已通过清单：

- 新聊天可以激活外贸业务助手并查看五个技能；未启用或不可见插件不会注入原生业务工具。
- 场景一可从对话创建询盘、核验公开来源、报价/下载、生成草稿、安排与结束跟进；工作台能看到同一条记录。
- 场景二能导入本会话附件，确认之前不生成；确认后资料卡的文件可下载，工作台可查看同一资料包。
- 场景三能从聊天建立协同单，按依赖逐项提交并等待用户真实审核，下载与当前版本一致的内部交接稿；不能自动代替用户批准任务。
- 修改后的报价或资料输出来自新回执，刷新聊天仍能继续查看可用的结果卡。
- 其他账号不能读改记录或导入本账号附件。
- 模拟报价、真实公开资料、第三方照片许可和 HugAgentOS 开源署名始终保留。

## 本地化与规则审阅（0.4）

新增第五技能 `localization-review` 与第八个原生工具 `trade_review`。先读取已有询盘或确认产品资料的实际版本，再 knowledge 检索规则、review 保存草稿校验；第二轮传真实 previous_review_id，展示风险变化。阿里RFQ为销售场景，Amazon美国站非媒体Listing为运营场景；标题与Item Highlights按当前知识版本分别检查。校验结果提供文字批注和风险标记，不作法律认证或发布批准。完整问答、字段、数据流与失败用例见 [赛题演示手册](HACKATHON_DEMO.md)。
