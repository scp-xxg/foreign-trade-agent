# 成交工作流

入口：对话框＋ → 工作流 → 成交。可再次点击关闭，与获客、背调、沟通、谈单、复盘互斥；保留会话隔离与排队消息发送时配置。

六技能：成交准备度检查 → 最终订单条款核对 → PI与销售合同草拟 → 签署与下单推进 → 收款条件与到账核验 → 订单交接与履约启动。模型依据企业和客户流程编排，PI可以在PO前，账期与信用证走对应规则，缺资料可补齐后重跑，变更后重新检查受影响步骤。

输入：订单号、带时区截至时间、企业成交及执行规则、PO/报价/规格各版本与往来、完整批准模板、签署记录、受控收款资料、付款节点应收与币种、银行或财务证据、交接部门和要求。模板字段用{{field}}，模型逐项引用证据并调用trade_buyer_research六个action；详见六技能references/contract.md及schema.json。

输出：六阶段状态、来源与版本、阻塞项/责任人/期限/依赖、条款差异、PI合同正文草稿、手续进度及待审消息、收款差额与异常、交接字段和前置条件。合同PI当前是可编辑正文，不自动导出DOCX/PDF。缺模板或材料明确待补，不伪造文档。

程序执行严格输入、原文引用、规则与依赖、字段比较、模板填充及Decimal计算。语义等价、签署权限、合同有效性、来源真实性及真实商业承诺仍需人员审核。来源类型与批准标志是输入声明；所有结论pending_review。账户来自受控资料，模板固定账户也须检查。只算货品小计，不擅加税费运保费折扣；最终应收来自确认条款。

水单及承诺不算到账，银行/财务资料还需匹配订单、账户、币种、付款方、日期；同一输入交易ID拒绝重复。跨调用和全量银行记录去重未接入，款项分配由财务复核。账期/信用证不强制预付；到账不等于可投产。交接须规则完整、条件支持且资料齐备，输出仍为待审核/接收；不声称已查产能或接收完成。

当前不自动发信、签署、生成签章、保存CRM、认领款项或启动生产。技能只生成待审结果；真实银行、签署、任务与执行系统需要另接真实工具及授权。

验收：独立材料标注缺项、版本差异、状态、字段和付款异常；人工核算金额。重点监测错误放行、误判到账、未批准账户替换为0；记录准确率、召回率、误报率、制单耗时、返工及交接完整率。业务效果单独记录成交周期与差错率并提供分母、周期、可比客户范围，未测不宣称效果提升。
