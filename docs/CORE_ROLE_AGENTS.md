# 三个核心外贸子智能体

本次只新增三个核心岗位；保留账号已有的其他助手。它们是可独立选择、也可由主助手通过call_subagent实际委派的子智能体，不只是协同单里的岗位标签。

## 岗位分工

| 子智能体 | 主责与产出 | 交接给谁 | 职责边界 |
|---|---|---|---|
| 外贸业务员 | 客户需求澄清、买家证据、询盘保存、RFQ待审回复与跟进 | 采购跟单员：询盘ID、版本与明确需求 | 不自行定价、承诺库存或交期，不外发 |
| 采购跟单员 | 产品规格/MOQ/包装核对、确定性报价、生产与运输风险清单 | 业务员与运营：报价编号、费用范围、规格来源与未知项 | 不修改客户需求，不虚构供应商进价或采购已下单 |
| 商品运营专员 | 同商品资料确认、英文文案/FAQ/三图/ZIP、Amazon草稿审核与迭代 | 业务员：资料包/审核ID、下载卡、待确认项 | 不改报价、不补造认证、不自动上架或代替人审 |

这是一种适合中小外贸团队的三岗组合，不代表所有公司使用相同组织架构。职责参考[O*NET批发销售岗位](https://www.onetonline.org/link/summary/41-4012.00)、[采购岗位](https://www.onetonline.org/search/task/choose/13-1023.00)、[电商运营岗位](https://www.onetonline.org/link/summary/13-1199.06)。单证与交付核对参考[美国商务部出口单证说明](https://www.trade.gov/documents-export-transaction)，实际适用要求仍取决于货物与目的地。

三个角色共享本账号外贸插件，按系统提示分工；这不是三套互相隔离的数据库权限。企业知识库默认不自动绑定，避免把私人知识随模板共享。真实供应商采购、发邮件、商品发布及最终合规批准不由这些角色自动完成。

## 队友安装与使用

从main拉取后，按TEAM_SETUP完成setup和原账号install：

~~~bash
.venv/bin/python extensions/foreign_trade/team.py install --app-home "$TRADE_APP_HOME" --username "$TRADE_USERNAME"
~~~

首次init也会安装。只有有创建智能体权限的账号才会创建角色；无权限时输出permission_required，由管理员显式授权后重新install。脚本按角色标识识别已有角色，多次执行不会多建；已有提示词、名称与人工配置保留。配置源为extensions/foreign_trade/core_roles.json，ID和账号绑定在各自实例生成，不提交运行数据库。

刷新页面，在能力中心→智能体可以看到三个角色。单独提问可选择对应角色；三岗合作从普通主聊天发起，按下方明确要求真实委派。保持外贸插件启用与main_agent模型可用。

## 可复制的协作任务

~~~text
请真实调用外贸业务员、采购跟单员、商品运营专员，按顺序共同完成一项任务，不由主助手扮演三个角色。
团队模拟买家Demo Office Buyer要DESK-001，500件，标准包装，目的国Spain，交期未知。
1. 业务员保存本次模拟询盘，只交回真实询盘ID与需求。
2. 采购跟单员读取同一ID，核对规格、MOQ并真实计算报价，交回报价与未知商务条件。
3. 运营专员沿用该ID建立协同接力，准备同款DESK-001候选规格与示意图，展示事实等待我确认。
下一岗必须使用上一岗的真实回执；不要新建不同商品来拼流程，不发送或发布，不代替人审。
~~~

看到运营返回的候选事实后，核对实际序号，再发送：

~~~text
确认采用刚才同一资料包候选事实1—6，保留模拟声明和图片许可。请真实委派商品运营专员确认并生成英文资料、FAQ、三图和ZIP，做Amazon草稿审核；完成后交给外贸业务员汇总客户待审回复和下载入口。采购报价保持不变，未知运税、认证和保修不作承诺。
~~~

若候选不是六条，以实际内容为准。生成需要明确确认；仅有岗位名称和文字对话不能算工具执行完成。

## 模拟对话脚本

以下是用于讲解的模拟脚本，金额来自项目确定性目录，实际措辞与ID以运行回执为准，不将脚本当作真实执行日志。

用户：请三岗协作处理500件标准包装DESK-001到Spain，先准备报价和资料候选。

外贸业务员：已保存模拟询盘，数量500、标准包装、目的国Spain，交期未知。请采购读取此询盘ID核价；买家身份和采购意愿未核实。

采购跟单员：已读取同一询盘并核对目录，MOQ为100件；500件适用USD4.80单价，标准包装附加费0，小计USD2400。运费和税费未计入，参考生产周期15天需确认且不含运输。将报价编号及规格来源交给运营。

商品运营专员：沿用同一DESK-001准备候选资料：PP、24×15×12cm、灰/白可选等，图片是CC0虚构示意图。请先确认原候选事实，再生成资料；不会自动上架。

用户：确认原候选1—6，生成资料并审核，最后让业务员汇总。

商品运营专员：已按确认事实生成英文资料、FAQ、三图及ZIP，附平台稿审核。资料和价格均为模拟；付款、贸易术语等仍待确认。将资料包和审核编号交回业务。

外贸业务员：汇总报价USD2400及英文资料入口，保留不含运税、交期和其他待确认条件，形成未发送的中英客户回复。未改变采购结果，未向客户外发。

## 检验标准

- 界面/API真实存在且能选择三个不同agent_id，各自绑定当前账号的外贸插件。
- 主聊天中出现三个call_subagent回执，下一岗读取上一岗保存的同一记录；检查子调用实际工具，而不只看自然语言。
- 业务保存需求、采购真实核价、运营准备同商品资料并等待确认；不能把主助手完成的工作归给子智能体。
- 金额500×4.80=2400；包装0；运税未知；运营产物仍需确认和人审。
- 重复install不新增副本，不覆盖人工配置，不改变账号权限；不同账号生成独立角色ID。
