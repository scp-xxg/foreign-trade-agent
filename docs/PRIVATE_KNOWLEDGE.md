# 本地私有知识库

本公开项目保持本地部署（DEPLOY_PROFILE=local），团队启动脚本开启 LOCAL_PRIVATE_KB_ENABLED。仅接通我的空间中的私有知识库，不同时开放云文档。原文和知识条目只对所属账号开放。

## 使用

1. 打开 /my-space/kb/private，新增知识库并填写名称、简介。
2. 当前只有对话模型、没有 embedding，默认采用 Wiki。Wiki 使用 kb_wiki 角色，未单独指派时回落 main_agent；生成会使用模型额度，并将待整理原文发送给所配置的模型服务。它不是离线生成，也不是向量语义检索。
3. 默认选择聚焦粒度和结构感知分块。上传文本型文档，预览后确认。扫描图片仍需单独配置图像理解或解析能力。
4. 已索引表示原文分块已保存；Wiki 是随后的异步生成任务。等待条目生成后，浏览目录、检索条目并打开原文出处。
5. 在对话中要求查询该知识库并引用原文。Wiki 地图用于定位，事实依据来自原始文档分块。

配置可用 embedding 后可另选 RAG。当前真实演示采用 Wiki，不声称向量检索已配置。缺少 embedding 时，向量索引和嵌入语义分块会在写入前拒绝，不先删除旧分块。

名称、简介和生成要求可直接保存；更改索引方式不自动重建已有资料，应显式重新索引或生成。Wiki 的原文证据分块只读，修改资料时应更新原文后再生成，避免条目与出处不一致。

## 旧账号没有新建按钮

新建本机管理员已带私有建库权限。升级前管理员可能没有开启；核对实例和账号后，由本机维护者显式执行：

```bash
cd /path/to/foreign-trade-agent
.venv/bin/python extensions/foreign_trade/enable_private_kb.py \
  --app-home /absolute/path/to/existing-app-home \
  --username YOUR_EXISTING_ADMIN --enable-create
```

命令先创建权限0600的SQLite快照，只修改指定现有管理员的 can_create_private_kb，保留密码、其他能力和业务数据并写审计。它不创建账号、不提高账号角色。完成后刷新页面；不要复制他人的数据库或模型密钥。

## 可重复演示

示例：[sample_followup_handbook.md](../extensions/foreign_trade/demo_knowledge/sample_followup_handbook.md)。金额、产品、规则均为团队模拟，与 DESK 报价目录独立。

创建“外贸样品与跟进知识库（演示）”，采用 Wiki / 聚焦模式上传示例，等待生成后提问：

> 请查询外贸样品与跟进知识库（演示）：KB-PACK-7316 每套几件，样品费多少，包含运费吗？请定位条目并引用手册原文。

预期：3件、18.50美元、不含运费；必须有实际检索和原文出处。

> 客户签收样品35天后才确认1000套，能否承诺退样品费？分别核对两个条件并引用原文，不发邮件。

预期：1000套满足至少800套，但35天超过30个自然日。两个条件必须同时满足，不能自动承诺退款。须保留模拟声明。

## 存储与异常

- SQLite：kb_spaces、kb_documents、kb_chunks、kb_wiki_jobs、kb_wiki_pages、kb_wiki_folders。
- 原始文件存于当前 app-home 的 storage；账号、模型配置和知识内容不随 Git 分发。
- HTTP 与 Wiki 工具继续执行原有账号归属校验，修改仍需权限。
- 队列持久化，模型或网络失败保留真实状态，不伪装成生成完成。
- 新库默认生成预算100次模型调用/批。大批资料需核对任务状态及实际覆盖情况。

本机实际验收证据在 ignored .runtime/kb-connection/，单测使用隔离数据库，不能代替模型和网页验收。
