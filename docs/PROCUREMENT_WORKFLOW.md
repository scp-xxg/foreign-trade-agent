# 采购工作流

对话框「+ → 工作流 → 采购」开启，当前会话保留开关，与其他工作流互斥。七技能内置于能力中心，并打包在外贸插件中。会话由模型读取技能、收集输入、实际调用 `trade_procurement_prepare(action,data)`，逐阶段推进；不是持久化工作流引擎或后台定时任务。

|阶段/action|技能|主要输入|可核对的输出|
|---|---|---|---|
|requirements|trade-procurement-requirements|规格版次、需求数量单位、日期地点、库存/在途/安全库存、确认记录|需求缺口、冲突、询价草稿|
|sourcing|trade-supplier-sourcing|可用搜索工具取得的或用户导入的候选、准入条件、来源、主体审核|候选去重、准入证据矩阵、缺口|
|capability|trade-supplier-capability|工艺与履约条件、产能和已承诺负荷、证据有效期|可用产能与需求比较、待核实项|
|comparison|trade-procurement-cost-comparison|报价、MOQ、费用口径、必计费用、汇率及有效期|货值、已知总成本、可比报价成本排名|
|quality|trade-procurement-quality-planning|样品版次、检查标准方法、上下限、实测值、责任人、审核|覆盖缺口、实测越界、质量待审清单|
|delivery|trade-procurement-delivery-tracking|真实PO与进度、节点依赖、更新时间、预计剩余自然小时|逾期、过期进度、依赖冲突、交付风险|
|settlement|trade-procurement-acceptance-settlement|批准PO、收货验收退货、发票、确认付款及贷项|数量质量差异、申报余额、可核对余额|

## 输入与操作

用户先提供产品、规格及版次、数量单位、交付日期和地点。库存、在途和安全库存必须是确认快照，明确无库存也要记录为0。净采购量=max(0,需求+安全库存−可用库存−确认在途)。未确认时草稿显示毛需求供讨论，不产生有效比价排名。复购可复用有效证据，跳过阶段必须说明依据。

模型将原文与引用组织为统一 `ProcurementInput`，每个技能的 `references/schema.json` 为实际Pydantic模型生成的完整JSON Schema，`references/contract.md` 说明字段语义；用户无须手写JSON。各阶段共用case_id、需求行ID、SKU/revision和来源。每次工具调用返回as_of和input_hash；版次、日期和输入变化后须重算受影响阶段，不能沿用旧审批。

最小空案测试输入：`{"case_id":"P-1","as_of":"2026-11-01T00:00:00+08:00"}`。调用requirements返回needs_input，而非成功采购。实际有需求时必须附来源和原文摘录，字段值必须在对应摘录中。所有时间带时区，币种使用三位大写代码。

报价费用为报价币种的绝对金额，汇率为1单位报价币种兑换多少比较币种；不推算税率、运费或零费用。缺项、过期、数量单位/版次/口径不一致时不参与排名。成本最低不等于供应商合格。

## 阶段推进与复用

需求 → 搜索候选 → 企业身份与交易风险审核 → 寻源/能力核对 → 询价与成本比较 → 样品/质量审核 → 采购条款与订单草稿。采购沟通与异议处理复用现有沟通及谈单能力。

模型取得真实批准PO后才进入交期阶段；有真实验收及发票再进入结算阶段。工具可用于对缺失数据进行诊断，但不能将诊断结果标为完成。资料不足时保留已完成步骤、展示阻塞原因并追问必要信息。模型逐轮展示七阶段状态、来源、责任人建议和下一步，最终组织采购准备包。导出仅提供真实文件链接。

## 审核与局限

该工具只检查传入证据及声明，不独立认证供应商或代替质检、财务。identity_reviewed、independently_checked、reviewed、approved、confirmed必须来自实际有权人员审核记录，模型不得自行填真。供应商自述不会自动视为已核实。部分内容仍需人工判断证据是否足以支持结论。

外部搜索使用当前环境可用的搜索/浏览能力；未连接时要求用户补候选，不能声称已联网寻源。没有ERP连接、自动发信、采购下单、生产放行、付款或后台持续监控。质量通过不等于大货放行，余额核对不等于付款授权。重复业务单据拒绝输入；改进版和重开票须人工清理版本，不自动推定抵销。

## 效果指标

技能文件分别给出人工标注准确率、候选有效率、能力误判率、可比报价覆盖率、样品标准覆盖率、预警命中率/漏报率、对账差异检出率等定义。时间节省、采购节省额、准交率和质量合格率须用真实执行记录和基线评估；缺少样本时工具返回null，不能把工具调用成功率当业务提升。当前实现包含确定性计算与异常测试，不宣称已经产生采购收益。
