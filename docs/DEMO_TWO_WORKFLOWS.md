# 现场演示：一条询盘，接力两个业务流程

目标用户是中小外贸企业的业务员与商品运营人员。输入客户询盘、商品资料和企业知识；A流程交付报价与回复，B流程复用同款商品事实交付上品素材。采购跟单员负责计算与费用边界，三个岗位在同一账号授权范围协作，不代表三个独立员工账户已互相授权。

## 演示前检查

1. 按[一键部署说明](ONE_COMMAND_DEPLOY.md)启动；以终端实际显示地址登录。维护者本机实例为3002端口，队友可使用不同端口。
2. 模型服务配置可用的对话模型并指派main_agent；打开三个角色，确认绑定外贸业务助手插件。普通中文问答需要真实模型，模板模式不会替代聊天模型。
3. 首次一键初始化已为自己的账号导入公开合规案例知识库；已有原生实例按部署说明导入。把企业资料放入自己的私有知识库。不要复制维护者的数据库、登录凭据或私有敏感词原文。主助手若要检索私有知识，请在当前会话明确选择所需知识库；岗位绑定不会自动打开主会话中的所有私人资料。未选择或未提供的企业政策应保留未知，不能称已验证。
4. 新建一个主助手聊天，保持同一会话完成全部步骤。下面每段可以直接粘贴，不必打开“+→工作流”的全部八个高级流程。主助手负责委派和显示卡片，业务写入由指定角色完成。
5. 保留每轮返回的inquiry_id、revision、collaboration_id、pack_id、review_id。下一轮说“刚才那条”仍应读取最新版本；若打开新会话，必须补填真实编号，不能编造示例ID。

演示标识：LYRECO是公开企业研究对象；DESK-001规格、价格、订单与合作关系全部为模拟。官网信息不证明来信人身份、采购意愿、信用或我方授权。下列金额来自随项目提供的模拟目录，不构成实际供货承诺。

## A：销售——公开资料、报价、RFQ与跟进

### 第1轮：业务员核验并登记

```text
请真实调用“外贸业务员”子智能体处理本轮，不要由主助手扮演岗位写入。
新建“销售到运营接力演示”：公开企业研究对象LYRECO，官网：https://www.lyreco.com/group/
此次询盘及合作关系完全模拟。
客户需求：DESK-001，500件，标准包装，发往Spain。要求交期、邮箱、注册国、付款条件和贸易术语未知。
先查询商品，再核对公开官网资料；事实要给来源和获取时间，无法核实的内容保持未知。保存模拟询盘，返回真实编号、revision并显示买家事实卡；正文只摘要重要事实和未知项，不粘贴完整buyer_card JSON。本轮暂不报价、不发送消息。
```

应看到真实子智能体调用、商品查询、询盘保存与公开核验回执；有官网事实/来源，未知项单列。外网失败时应报告失败或部分结果，仍能保存需求，不能声称核验完成。

### 第2轮：采购计算

```text
请真实调用“采购跟单员”，读取刚才询盘的最新版本并计算500件、标准包装、Spain的模拟报价。解释货值、包装费、生产参考周期及不包含的费用，返回真实报价编号与询盘版本。不改数量，不承诺实际到货日期，不替我批准付款条件。岗位完成后，允许主助手仅加载该插件所需的buyer-inquiry-followup技能并调用trade_inquiry action=get读取刚才真实询盘，展示原生报价和下载卡；主助手不得重算或代写。
```

应看到货值USD 2,400.00，额外包装费USD 0.00，小计USD 2,400.00；运费、税费等保持未确认。在询盘卡点击“查看事实、草稿与待办”，详情顶部会读取并显示当前报价卡，再点击“下载中英文PDF”和“下载中英文Excel”；核对两文件金额、币种和报价编号一致。

### 第3轮：第二次对话改量重算

```text
客户把刚才同一条询盘改为1000件，并要求定制包装，目的国仍是Spain，其余未知项不变。请先由外贸业务员保存明确变更，再交采购跟单员重新计算。必须沿用同一inquiry_id，返回新revision和新quote_id，并说明旧报价已失效。岗位完成后，主助手只读调用trade_inquiry action=get展示当前报价卡，不代写或再次重算。
```

应看到USD 4,800.00货值＋USD 300.00包装费＝USD 5,100.00；旧草稿/报价失效，重新生成后才能作为当前版本导出。不要重新创建第二条询盘。

### 第4轮：RFQ草稿与第一轮审核

```text
请外贸业务员读取当前1000件定制包装报价，生成面向Alibaba RFQ的英文回复和中文审核稿。保存中英回复草稿，明确这是演示报价、不含运费税费，付款/有效期/Incoterms未知。
先读取“外贸合规范围与证据核验”及localization-review技能，检索企业知识和适用Spain/EU的公开合规案例，再用trade_review真实审核当前询盘和草稿，展示文字批注、风险标记与来源；不要把普通PP收纳盒一律判成必须有CE认证。完成一次审核即返回，保留待修改项，等下一轮再改稿。
另外为我创建一个站内跟进待办：2030-01-02 09:00 Europe/Madrid，主题“确认包装稿与运费”。该时间是可重复演示用日期，不对外发送或建立发信计划。完成后主助手可只读trade_inquiry get和trade_review get展示当前报价、跟进与审核卡，不代写或重新计算。
```

应看到已保存草稿、跟进待办、审核卡；平台要求与商务费用/市场合规分别有来源。待确认不等于审核失败，也不能因此标为“完全合规”。

### 第5轮：改稿与复审

```text
请外贸业务员基于上一轮真实review_id修改回复：保持USD 5,100.00及各分项准确，删除无依据的认证、免运费或保证交期承诺，保留未知项，并用简短自然英文询问收货信息及包装稿要求。必须使用trade_inquiry action=update_drafts、data仅含完整zh和en两个字段，真实保存修订稿；保存成功后以返回的新revision重新审核，关联上一轮review_id，展示已解决和仍需确认的问题。不要发送消息。
```

应先看到update_drafts保存回执和新的询盘revision，中文/英文分别存入drafts.zh与drafts.en；再看到新审核编号、前后变化与仍待确认项。不能把双语文本拼进审核body代替实际保存。若来源版本因保存草稿变化，报告应明确source_changed，不得假装两次输入完全相同。下载最终审核Markdown/JSON和当前报价PDF/Excel。不得把截图、打印对话或旧报价当最终导出。

## 接力：同款商品与运营任务

### 第6轮：创建关联资料包

```text
请外贸业务员为刚才同一条询盘创建岗位协同记录，自动准备同款DESK-001模拟目录资料包。必须关联真实inquiry_id与当前报价，返回collaboration_id和content_pack_id，关系为同款交易资料；不能混入其他商品资料。
指派商品运营专员准备图片、英文资料和FAQ；采购跟单员核对供货条件。仅建立任务及候选事实，先展示候选事实和图片来源，暂不替我确认事实、生成素材或验收完成。
```

应看到关联同一DESK-001的协同卡、真实资料包编号、候选6条事实、待办状态。图片应标记为程序绘制的虚构几何示意图，不能当真实照片。事实确认前不能生成资料包。

## B：运营——英文资料、三图、Amazon US与复审

### 第7轮：确认事实并生成

```text
我确认刚才同款DESK-001资料包中的6条模拟目录候选事实仅用于演示：型号DESK-001；名称Modular Desk Organizer；材质PP；尺寸24×15×12 cm；颜色gray、white；范围Simulated catalog, not a real supplier offer。图片是项目原创CC0虚构示意图，不是实物照片。
请真实调用“商品运营专员”，先读取最新资料包并核对候选内容，再确认这6条，生成英文资料、FAQ及1:1、16:9、3:4三种排版图片，返回真实pack_id和revision以及原生下载卡。
使用ai模式；模型若失败必须明确报告回退模板，不能称AI生成成功。不要补造库存、认证、保修或销售授权，也不发布商品。岗位完成后，主助手只读trade_product_content action=get读取真实pack_id，展示原生英文资料、三图和ZIP下载卡，不代写或再次生成。
```

应看到`method=ai_grounded`或明确说明回退模板；有真实英文内容、9条FAQ和3张PNG。尺寸分别为1200×1200、1600×900、1200×1600。上传原图时做原图排版；本例用模拟示意图。模板模式也能生成可下载资料，但不能冒充AI图片或模型产出。

### 第8轮：Amazon US稿与市场审核

```text
请商品运营专员沿用刚才pack_id和最新revision，面向Amazon US生成英文Listing草稿，包含简洁标题、item_highlights、要点和描述，基于已确认事实，不把Spain报价当美国售价。
检索美国及Amazon适用规则，用trade_review审核实际草稿，给出来源版本、文字批注和颜色风险；同时显示与EU示例适用范围的差异。检测不等于认证批准，图片不能自动声称符合Amazon主图全部要求。
```

应看到基于同一商品资料包的Amazon审核卡，目标en_US，规则来源可查看。标题限制以实际检索到的版本与适用范围为准，勿背诵过时数值。主图/示意图/版权/平台类目不适用项应保留待人工确认。

### 第9轮：第二轮修订及最终下载

```text
请商品运营专员按刚才Amazon审核结果缩短冗余措辞，删去无依据宣称，保持已确认规格不变。用相同content_pack作为事实来源，关联previous_review_id再次审核，展示前后差异。请分别给出基础英文资料包/三图ZIP下载卡，以及包含最终Amazon改稿的审核Markdown/JSON下载卡。
最后由主助手只读汇总本次inquiry_id、quote_id、pack_id、两个场景的review_id与未决事项。允许主助手只读调用trade_inquiry get、trade_product_content get和trade_review get，以岗位返回的真实编号显示三个原生下载卡。不要重建记录、重新生成已完成图片或标记任务已被人工验收。
```

如果子智能体仅返回文字，主助手需要按上述指令真实get读回记录，才会渲染原生卡；不能把子任务文字里的“可下载”当作卡片已经出现。主助手读回同样需要先完整读取该安装的正确技能，不能用同名内置背调技能替代。

最后点击并打开：

- 报价卡：展开当前询盘详情后下载中英双语PDF、双语Excel，报价编号与金额匹配当前有效报价；保存草稿或新增待办导致询盘版本增加，不会要求重新计算未变化的报价。
- 资料卡：英文资料、FAQ CSV、三张PNG、ZIP。ZIP含`english-listing.md`、`customer-faq.csv`、`facts.json`、来源说明及三图。
- 审核卡：Markdown与JSON，包含最终Amazon稿、批注、规则来源及前后变化。

**资料包是基础产品素材；最终平台改稿在审核报告中。复审不会自动覆盖原ZIP内的基础英文Listing。** 展示时同时打开两类文件，避免把基础包称为最终Amazon发布包。整个流程不会外发邮件、上传Amazon或取得实际供货/认证批准。

## 可重复性与故障说明

- 同一询盘与资料包用真实编号接力；不同账号无权读取。修改数量使报价失效，修改事实使生成物/旧审核过期，必须按提示重算或复审。
- 每轮出现工具错误先停在当前记录，不重复新建或虚构成功；409时读取最新revision再重试，401重新登录。
- 模型不可用时可在辅助工作台选择“本地原文模板”检查本地导出链路，明确说明没有完成真实模型对话。公开网页失败可展示已存证据及其日期，不能称为实时核验。
- 自动回归：`PYTHONPATH=src/backend:extensions .venv/bin/python -m pytest -q tests/test_two_workflow_journey.py`。该测试真实执行数据库、报价、两轮审核、同款接力和ZIP/PNG解析，公开研究使用明示离线fixture；它不代替真实模型、外网和浏览器PDF下载验收。
