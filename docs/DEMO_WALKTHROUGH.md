# 三场景演示手册

本手册以**工作台＋显式本地原文模板**为当前可靠主线，不需要模型完成业务操作。公开买家核验需要访问互联网；“不调用模型”不等于所有步骤都不联网。另在文末提供有可用模型时的聊天提示和确认顺序。

截至 [2026-10-28 验收记录](ACCEPTANCE_20261028.md)，三场景工作台流程及实际文件已核验；真实模型连续聊天因 HTTP 500 未通过，模型问题目前暂停处理。本文核对当前公开源码的按钮和字段，不将本地流程写成模型聊天已通过。

## 演示前准备

1. 从公开仓库取得最新 `main`，按 [TEAM_SETUP.md](TEAM_SETUP.md) 安装或升级自己的实例、启动并登录。已有实例保留自己的账号和数据目录，不复制他人的数据库或模型配置。网页地址以启动输出为准：默认是 `http://127.0.0.1:3001`；3001 属于其他容器或服务时保持它不动，用 `team.py start --app-home 原数据目录 --port 3002` 启动本项目，再打开 `http://127.0.0.1:3002`。对应的 `check --running` 也须传同一 `--port 3002`，完整命令见部署指南。
2. 确认三个工作台入口可用：**询盘工作台**、产品内容入口（页面标题为 **商品资料工作台**）、**跨岗位协同**。插件版本为 0.3.0，包含四个技能、七个原生业务工具和三个独立目录 MCP 工具。
3. 准备下列仓库文件。浏览器在 Windows、源码在 WSL 时，可用 `wslpath -w "$PWD/extensions/foreign_trade/demo_product/product_facts_en.csv"` 查看文件选择器可用的路径；不要把路径当成已上传的聊天附件。

| 文件路径，相对仓库根目录 | 用途 |
|---|---|
| `extensions/foreign_trade/demo_product/product_facts_en.csv` | Pi 的 8 条既有英语事实，保留来源与核验日期 |
| `extensions/foreign_trade/demo_product/raspberry-pi-5-original.jpg` | Pi 的许可原图 |
| `extensions/foreign_trade/demo_product/PHOTO_LICENSE.txt` | 作者、来源、CC BY 4.0 许可和改编署名 |
| `extensions/foreign_trade/demo_product/desk-001-demo-specs.csv` | DESK-001 的 6 条模拟英语事实 |
| `extensions/foreign_trade/demo_product/desk-001-demo-schematic.png` | 程序绘制的模拟几何示意图，不是真实产品照片 |
| `extensions/foreign_trade/demo_product/desk-001-demo-sources.json` | DESK 模拟来源、CC0 声明和文件哈希 |

后三个文件会由场景三自动准备流程使用，通常无需手工上传。每次演示新建自己的记录，例如标题加“演示 A”，避免覆盖同事或自己已有的人工编辑。

## 场景一：LYRECO 公开资料与模拟询盘

### 输入与保存

打开 **询盘工作台**，点击 **新建询盘**，填写：

| 页面字段 | 演示输入 |
|---|---|
| 询盘标题 | `演示 A · LYRECO DESK-001` |
| 买家公司 | `LYRECO` |
| 公司官网 | `https://www.lyreco.com/group/` |
| 买家邮箱（可留空） | 留空，不编造联系人 |
| 公司所在国（未核实可留空） | `FR`，用于本例的登记国检索 |
| 这是团队构造的演示询盘 | 保持勾选 |
| 询盘原文 | 下方完整文本 |

```text
TEAM-CREATED DEMONSTRATION ONLY. This is not an actual LYRECO inquiry, order or business relationship.
Please quote 1000 units of DESK-001 Modular Desk Organizer with custom packaging for delivery to Spain.
Please provide specifications, MOQ and indicative production lead time. Production days are not specified.
Freight, taxes, duties, shipping time and other commercial terms require separate confirmation.
```

点击 **保存询盘**，再点击 **核验公开信息**。查看 **买家事实卡** 和 **公开来源与获取状态**：官网自述、登记匹配、来源及获取时间应分别呈现。公开信息不证明来信身份、信用、采购意愿或交易关系。网络失败或无记录时保留“未核实”，不要改写成核验成功或不可靠。

无模型演示不点击 **提取询盘需求建议**，直接手工填写下面的结构化条件。右上角 **体验 Lyreco 公开资料示例** 是另一种起点，但它预填 **500 件、标准包装**；若使用它，必须同时修改原文和数量/包装字段，才能得到本手册的 5100 报价。

### 产品、报价与下载

在 **产品与报价** 中：

1. 在 **产品名称或 SKU** 输入 `DESK-001`，点击 **查询产品**，查看模拟规格、起订量、阶梯价和定制包装条件。
2. 点击 **加入报价**。该按钮会先填目录 MOQ 与标准包装，**必须再把采购数量改为 `1000`，包装方式选为 `定制包装`**。本例只保留一个 DESK-001 产品行。
3. **交付目的国** 填 `Spain`，**期望生产周期（天，可留空）** 留空。公司登记国 FR 不替代交付目的国。
4. 点击 **确认条件并计算报价**。页面会先保存尚未保存的条件，再计算。

应看到以下模拟结果，金额以实际工具/页面回执为准：

| 项目 | 预期 |
|---|---:|
| 数量 | 1000 件 |
| 商品单价 | USD 4.80 |
| 每件定制包装费 | USD 0.30 |
| 货值 | USD 4800.00 |
| 包装费 | USD 300.00 |
| 不含运费及税费小计 | **USD 5100.00** |
| 参考生产周期 | 18 天，须确认，不包含运输时间 |

在 **中英文报价单** 卡片点击 **下载中英文 PDF**、**下载中英文 Excel**。文件名分别为 `<报价编号>-ZH-EN.pdf`、`<报价编号>-ZH-EN.xlsx`；浏览器可能给同名下载追加序号。

打开文件检查 DEMO 标记、1000 件、4800＋300＝5100、目的国 Spain，以及运费/税费未计入。Excel 应有“中文报价单”和“English Quotation”两张表。它是已计算快照，修改 Excel 中的数量不会自动重新报价。

### 回复草稿与跟进

1. 点击 **生成中英文回复草稿**，切换 **回复语言** 检查中文与 English。这里使用已保存事实和确定性业务模板，不要求调用模型。
2. 草稿应包含当前报价和待确认条件；**复制草稿** 只是复制，不会向客户发出邮件。
3. 在 **跟进事项** 填：`演示跟进：核对包装图稿和运费，未实际联系客户`。
4. 在 **跟进时间** 选择一个未来时间，例如 `2026-10-30 09:00`。如果演示时该日期已过，请改用自己的未来日期。字段下方显示浏览器实际时区；若要上海上午 9 点，应确认显示 `Asia/Shanghai`。这里没有单独的时区下拉框。
5. 点击 **添加跟进待办**，检查时间和状态。然后作为本次模拟操作，点击 **标记客户已回复**：未完成待办应变为“已取消”，页面说明客户回复已记录。真实演示中并未联系 LYRECO。

这条已保存的 DESK 询盘继续用于场景三。只读查看或添加跟进待办不会改变产品事实和报价依据。

## 场景二：真实 Pi 资料，用本地模板制作英文内容

### 建立资料包并上传

打开 **商品资料工作台**，点击 **新建 Raspberry Pi 5 示例**。该按钮填充元数据与署名，**不会自动上传文件**。核对或填写：

| 页面字段 | 演示输入 |
|---|---|
| 资料包标题 | `演示 A · Raspberry Pi 5 英语资料` |
| 产品名称 | `Raspberry Pi 5` |
| 品牌 | `Raspberry Pi` |
| 产品型号 | `Raspberry Pi 5` |
| 主要资料来源 | `https://www.raspberrypi.com/products/raspberry-pi-5/` |
| 图片来源与授权署名 | 下方署名，或核对页面预填的同等完整署名 |

```text
Photo: SimonWaldherr, Raspberry Pi 5.jpg (CC BY 4.0). Layout and text added; original photo retained. Source: https://commons.wikimedia.org/wiki/File:Raspberry_Pi_5.jpg License: https://creativecommons.org/licenses/by/4.0/
```

点击 **保存资料**，再用 **选择文件上传** 实际上传：

- `extensions/foreign_trade/demo_product/product_facts_en.csv`
- `extensions/foreign_trade/demo_product/raspberry-pi-5-original.jpg`

页面应显示两份已上传资料和原图预览。无模型英语路线可直接使用工作台的 **下载英文事实 CSV**，取得 `product_facts_en.csv` 后再从 **选择文件上传** 导入；也可使用上表中的同名仓库文件。原 **下载示例事实 CSV** 仍提供双语示例，导入时可能优先取中文列。**下载授权原图** 可作为取得许可图片的另一入口，但仍须实际上传到自己的资料包。

### 确认并生成

1. 查看 **从资料中提取的待核对字段**，逐项对照 CSV 与来源，再点击 **加入事实表，逐项核对**。
2. 核对共 **8 条**事实；不根据照片补猜 RAM 容量，不增加售价、MOQ、库存、保修或经销授权。
3. 点击 **保存资料**。保存和任何资料修改都会取消之前的确认勾选。
4. 在 **生成方式** 选择 **本地原文模板（不调用模型）**。默认值是 **AI翻译与生成**，无模型路线必须显式切换。
5. 人工核对后，勾选 **我已对照来源逐项核对产品事实，并确认图片可用于本次制作。**
6. 点击 **按原文模板整理资料**。

成功后应显示 **本地原文模板（未调用模型）** 和 **尚未发布**。此模式只整理确认后的原文、不翻译，英语资料必须由用户确认其原文已是英文；若仍有中文名称/事实，英文图片会暂停生成。没有确认或没有图片署名时，不应绕过提示继续。

### 审阅与下载

在 **审阅并下载商品资料包** 中检查：8 条事实、**11 条 FAQ**，以及以下三图：

| 页面名称 | 尺寸 | 下载文件 |
|---|---|---|
| 方形商品图 | 1200×1200 | `product-square.png` |
| 横版展示图 | 1600×900 | `product-landscape.png` |
| 规格信息图 | 1200×1600 | `product-spec.png` |

按钮 **下载文案**、**下载 FAQ**、各图的 **下载 PNG**、**下载全部资料 ZIP** 对应：

- `english-listing.md`
- `customer-faq.csv`
- 上表三张 PNG
- `product-content-pack.zip`

ZIP 应含 **8 个文件**：上述文案、FAQ、三张图，以及 `facts.json`、`provenance.txt`、`uploaded-sources.json`。检查原事实、来源、SimonWaldherr/CC BY 4.0 署名和“本地模板未调用模型”说明；未知商务条件仍待确认。来源文件和照片不构成采购或经销关系。

本场景的 Pi 产品与模拟 DESK 目录独立。不要在页面下方“从演示目录衔接询盘报价”区域把 Pi 规格当成 DESK 商品，或将 DESK 模拟价格用于 Pi。

## 场景三：同一 DESK 订单的五角色、六任务

### 建单并准备同订单资料

1. 打开 **跨岗位协同**，展开 **从已有询盘创建协同**。
2. **协同标题** 填 `演示 A · DESK 订单岗位协同`。
3. **来源询盘** 选择场景一保存的 `演示 A · LYRECO DESK-001`，核对是当前 1000 件定制包装、Spain、USD 5100.00 的记录。
4. **产品资料包，可选** 留空，点击 **创建协同**。不要选择场景二的 Pi 资料包。

当前自动准备仅支持单一 DESK-001 产品行。系统会为该询盘建立有目录绑定的 DESK 候选资料包，包含 6 条英语模拟事实和 CC0 几何示意图；不会自动确认事实、生成内容或完成任务。

在协同单 **产品资料包** 来源卡点击 **查看来源**，精准进入本单的资料包。不要仅按同名标题挑选另一个包。核对候选事实和“程序绘制、非真实照片”声明，依次 **加入事实表，逐项核对 → 保存资料 → 生成方式：本地原文模板（不调用模型）→ 勾选事实与图片确认 → 按原文模板整理资料**。

应得到 **6 条事实、9 条 FAQ、三种相同尺寸图片和 8 文件 ZIP**。图中应保留模拟标记，通用称呼为 `image`，不称为真实照片；CC0 署名保留。下载入口和文件名与场景二相同，须用标题、原图、SKU 和事实内容区分两份资料。

返回 **跨岗位协同**，选中本单，点击 **更新来源版本并重置受影响验收**。这只接受新版依据，不等于任务已通过审核。

### 五种角色与六项任务

页面角色显示“销售、采购、设计、运营、合规”，其中销售对应业务岗位，设计对应美工岗位。可以使用下列演示负责人标签及结果说明；**只有实际核对过对应页面和文件后才填写这些结论**。

| 顺序与任务 | 页面角色／负责人姓名标签 | 必需依赖 | 可填写的工作结果与证据 |
|---|---|---|---|
| 1. 确认需求和买家资料 | 销售／`演示业务岗` | 无 | 已核对模拟询盘原文、1000 件定制包装、Spain；公开来源与真实交易关系分别标注。 |
| 2. 核对供货条件和模拟报价 | 采购／`演示采购岗` | 任务 1 | 已核对当前报价货值 4800、包装费 300、小计 USD 5100；运费、税费和实际供货未确认。 |
| 3. 准备产品图片素材 | 设计／`演示美工岗` | 任务 1 | 已查看本单 DESK 三张图片、尺寸、模拟示意声明和 CC0 署名。 |
| 4. 审阅商品文案与 FAQ | 运营／`演示运营岗` | 任务 3 | 已核对本单 6 条英语事实、9 条 FAQ 和原文模板说明，未写入额外商务承诺。 |
| 5. 审核来源和对外表述 | 合规／`演示合规岗` | 任务 2、4 | 已核对公开/模拟来源、图片署名与表述；实际认证、目标市场要求与销售资格仍待确认。 |
| 6. 汇总内部交接草稿 | 销售／`演示业务负责人` | 任务 5 | 已逐项核对本轮有效审核、当前来源与未决事项；仅供内部交接，未发信或发布。 |

负责人是**当前账号中的姓名标签**，不是五个独立登录账号，不构成多人 ACL。系统不会向这些标签对应的人发送消息或通知。审核记录中的操作人是当前登录用户。

### 每项任务的实际审核操作

按上表顺序，对每项任务分别操作：

1. 点击该任务的 **编辑与验收**。
2. 填 **负责人姓名标签**；**任务状态** 选 **待人工验收**。不要选择“已验收”，该值不能直接设置。
3. 填 **工作结果与证据**；保留并补充 **未解决事项，每行一项**、**风险提示，每行一项**。不要为让任务通过而删掉实际未知项。
4. 保留必需 **依赖任务**，点击 **保存任务**。
5. 在保存后的任务中，核对当前交付物、来源版本、前置任务与未解决事项；再填 **人工验收说明**，例如：`我已核对本任务当前材料和验收标准，知悉所列未决事项，确认用于本次模拟内部交接。`
6. 勾选 **我已核对交付物、来源版本、依赖与未解决事项。**，点击 **确认人工验收**。

用户没有实际查看并明确确认时，应停在待验收。一次“帮我处理”不等于六次审核授权。前置未完成、资料未生成、来源已变化或表单尚未保存时，审核按钮会被阻止；先处理提示，不改依赖去绕过它。

### 下载内部交接

全部六项任务有效验收后，应显示 **已验收 6/6**，没有来源失效或阻塞提示。点击 **下载交接 Markdown**、**下载交接 JSON**，得到：

```text
collaboration-<collaboration_id>-r<当前修订号>.md
collaboration-<collaboration_id>-r<当前修订号>.json
```

ID 和修订号来自自己的实际记录，不照抄历史验收中的数值。核对六项任务、五角色标签、依赖、审核意见、来源版本、未决事项和风险。JSON 应包含 `scope=current_user_role_coordination`、`messages_sent=false`、`published=false`。可内部交接不代表真实订单、已经合规或可直接发货。

### 演示来源变化和重新审核

1. 在该协同单的 **询盘** 来源卡点击 **查看来源**。把原文中的数量/包装和结构化字段同时改为 **500 件、标准包装**，保留 DESK-001、Spain。
2. 点击 **确认条件并计算报价**，应得到新的模拟小计 **USD 2400.00**；再点 **生成中英文回复草稿**，旧条件草稿不再作当前依据。
3. 返回协同单，点击 **刷新当前记录**。来源及受影响任务应提示变化，交接下载不再可用；之前已下载的文件仍是历史快照，不会自行更新。
4. 点击 **更新来源版本并重置受影响验收**，检查旧审核已退回需要复核的状态。重新查看本轮来源和结果，按依赖逐项保存、人工验收，之后才能下载新版交接稿。
5. 如果需要以最初 USD 5100.00 结束演示，再把原文及条件改回 **1000 件、定制包装**，重算、更新草稿、刷新协同来源并重新审核。不能复用改变前的审核结论。

这里展示的是版本失效控制，不会联系真实客户。不能把已存在的旧文件当作当前版本，旧修订下载请求会被拒绝，而不是自动替换为另一个已审核的新稿。

## 模型可用后：单独执行聊天路线

下列提示是待复测操作，不表示当前 HTTP 500 已解决。先按部署指南配置并验证自己的模型；新聊天输入 `/` 选择 **外贸业务助手（演示）**。需要看到实际工具调用、成功回执和当前状态卡，只有说明文字或 JSON 示例不算执行。

### 对话一：询盘、草稿与跟进

```text
请读取买家核验与询盘跟进技能，使用 LYRECO、注册国 FR、官网 https://www.lyreco.com/group/ 核验公开资料。
保存一条“对话演示 A · DESK-001”询盘：1000 件 DESK-001，定制包装，交付目的国 Spain，生产天数未指定。
这是团队构造的模拟询盘，不是 LYRECO 的真实邮件、订单或合作关系。
请查询产品、计算模拟报价、保存未发送的中英文回复草稿，保留来源与未确认条件；不要联系客户。
```

核对 USD 4800＋300＝5100 和实际记录后，再明确给出自己的未来日期、时间、时区要求创建站内跟进。需要演示结束跟进时明确说明“本次模拟客户已回复，请标记并取消未完成待办”。不要把站内待办说成保证推送或自动发信。

### 对话二：当前聊天附件与事实确认

先将英语 CSV 和许可照片**实际附到当前聊天**，再输入：

```text
请读取产品内容技能，将本次聊天附件导入新的 Raspberry Pi 5 资料包。
产品名称和型号为 Raspberry Pi 5，品牌为 Raspberry Pi，主要资料来源为 https://www.raspberrypi.com/products/raspberry-pi-5/ 。
请保留随附照片的 SimonWaldherr、来源、CC BY 4.0 及排版改动署名。
先展示8条候选事实、来源、图片许可和缺失商务条件，等待我逐项核对，不要现在确认或生成。
```

看过助手实际导入回执和候选摘要后，用户才发送第二步：

```text
我已核对本轮展示的8条英语事实和照片署名，确认采用这些候选事实。
明确选择本地原文模板，不调用生成模型、不翻译，不新增事实；请生成文案、FAQ、三种排版图和ZIP，保留未发布标记。
```

对应流程为 `trade_import_product` → `trade_confirm_product_facts` → `trade_product_content(action="generate", confirmed=true, data={"generation_mode":"template"})`；每步使用最新真实 ID/修订号。若用户需要 AI 翻译，可另行选择默认 `ai` 模式，但必须单独验证其真实结果。本地模板不调用生成模型，聊天本身的工具编排仍依赖聊天模型。

### 对话三：同订单协同与真实人工审核

```text
请读取跨岗位协同技能，使用刚才保存的“对话演示 A · DESK-001”询盘建立协同单。
请准备同一DESK-001模拟目录的候选资料，不要把Pi资料关联成本次交易产品。
负责人标签设为业务“演示业务岗”、采购“演示采购岗”、设计“演示美工岗”、运营“演示运营岗”、合规“演示合规岗”。
展示六项任务、依赖、验收标准和待确认事项；资料事实先让我确认，任务审核也逐项等待我看过当前产物后明确确认。
不向负责人或客户发送消息，不发布商品。
```

确认 DESK 候选事实后，使用产品内容技能生成本地模板，并刷新协同来源。每项任务先保存结果为 `in_review`，向用户展示实际依据；只有收到对该任务的明确确认后，才调用 `trade_collaboration(action="review")`。工具顶层传 `collaboration_id`、最新 `revision`、`task_id`，`data` 中只放 `confirmed` 与 `review_note`，不能让模型自行给六项任务批量通过。

如需补关联现有资料包，可通过 `trade_collaboration(action="link_content")` 指定当前记录和 `data.content_pack_id`、`data.content_relationship`。真实 Pi 资料只能选 `independent_reference`；`transaction` 必须通过同一模拟 SKU 的目录绑定检查。当前工作台没有独立的“关联已有资料”编辑按钮，不要寻找不存在的控件；工作台主线按上面的创建时选择或自动准备完成。
