# SailAgent 现场演示操作与示例问答

PR #7已合并到main。队友从main拉取即可获得同一套界面、技能和业务逻辑；账号、模型配置、知识库内容、上传文件和历史记录各自独立。本手册对应外贸插件0.9.0：以同一款DESK-001模拟商品贯穿销售与运营，展示数据、企业知识、规则反馈和岗位交接。保留Powered by HugAgentOS。

## 1 演示前准备

完整安装和升级见[队友部署指南](TEAM_SETUP.md)。赛前完成以下操作，现场不重新安装依赖或迁移数据库：

1. 启动公开实例并保持终端运行。本机用3002；3001属于其他服务，不要停止它。
2. 登录自己的账号。在“系统设置→模型服务”确认主对话模型测试正常，并指派main_agent；再用真实产品查询验证工具结果能够回传，不能只看连接测试。
3. 在“能力中心→插件”确认“外贸业务助手（演示）”0.9.0已安装启用。新聊天输入 /，从菜单实际选中插件；仅输入插件名称不等于已经选中。
4. 使用标准对话模式。聊天中的“快速”是模型速度档，不等于禁用工具的极速问答模式。
5. 提前打开或收藏：聊天、询盘工作台、商品资料工作台、协同工作台、私有知识库、用户管理。工作台是核对入口，主线仍从聊天发起。
6. 知识库环节必须提前上传示例手册并完成Wiki索引；市场环节提前确认管理员和成员权限。新部署不会自动获得维护者的知识库、账号或模型密钥。

本机服务已运行时直接打开http://127.0.0.1:3002/，不要重复执行start。若本机公开实例确实停止，在WSL执行：

~~~bash
cd /home/scp666/iChainAgent/foreign-trade-agent
.venv/bin/python extensions/foreign_trade/team.py start \
  --app-home "$HOME/.hugagent-hackathon-public-1.0.2" --port 3002
~~~

队友使用自己的数据目录和空闲端口，不能照抄维护者的app-home。新部署默认目录是~/.foreign-trade-agent，默认端口3001；端口冲突时另选3002等空闲端口。

## 2 演示顺序与节奏

| 顺序 | 操作 | 给评委看的证据 |
|---|---|---|
| A1 销售首轮 | 核验买家、查产品、保存1000件定制包装询盘并报价 | 官网/GLEIF来源、模拟声明、USD5100报价卡 |
| A2 销售第二轮 | 同单改500件标准包装，重算、刷新回复并保存待办 | 同一询盘ID、USD2400、PDF/Excel、带时区待办 |
| 接力 | 同单准备同款商品资料与协同单，等待事实确认 | 同一DESK-001、资料包ID、六条候选事实、图片许可 |
| B1 运营首轮 | 明确确认事实，生成英文资料、FAQ、三图与ZIP | 真实生成回执和下载卡，模拟图片标识 |
| B2 审核问题稿 | 基于同一资料检查RFQ及Amazon问题稿 | 平台规则+报价条款；风险颜色+文字批注 |
| B3 修改复审 | 修正运税承诺与颜色表达，关联前轮审核 | 2项高风险修复为0项，未知条件仍待确认 |
| 补充演示 | 企业原文问答、岗位状态、市场安装副本 | 原文出处、依赖/版本、真实审核与安装 |

每轮等工具完成再输入下一轮，不连续点击发送。模型与外网可能使单轮需要数分钟，不承诺固定耗时。短场可提前准备买家核验与首轮文件，现场真实操作“改量重算”和“问题稿复审”；向评委说明哪些记录是预先准备的，不能把历史输出冒充现场新调用。

建议A用一段聊天完成两轮；B可另开一段短聊天，提供A返回的询盘ID、资料包ID和协同ID，保持同一商品与数据关联。这样减少重复回传长历史。ID必须来自本人账号的真实回执，不照抄别人的演示编号。

## 3 A1 销售首轮

操作：新建聊天，输入 / 选择“外贸业务助手（演示）”，发送：

~~~text
请使用sales-to-listing技能处理一条团队构造的模拟询盘，非LYRECO真实订单。
稳定标题：现场演示·LYRECO·DESK-001。
买家LYRECO，登记国家FR，官网https://www.lyreco.com/group/。
产品DESK-001，1000件，定制包装，发往Spain，交期未指定。
先核验公开资料、查询并核对产品，保存询盘并真实计算报价，生成中英待审回复。
明确模拟数据、运费和税费另计，不发送客户消息，也不发布商品。
~~~

预期回答要点（数值为确定性结果，措辞不固定）：

- 官网与GLEIF分开给来源、核验时间及未核实事项。公开登记不证明实际来信人、采购意向、信用或合作关系；来源打不开时如实保留缺口。
- DESK-001：商品单价USD4.80，货值4800；定制包装每件0.30，包装费300；不含运税小计USD5100。
- 交期未指定；参考生产周期18天需确认，不含运输时间，不承诺到货日期。
- 回答带真实询盘ID和报价卡，中英回复标为待审、未发送。付款、有效期、贸易术语等未知条件保留待确认。

展示动作：展开“询盘处理记录→查看事实、草稿与待办”，点开一条来源；不要将来源查询成功描述成“买家信用已认证”。

## 4 A2 同单改量与跟进

在同一聊天发送：

~~~text
沿用刚才同一笔询盘，改为500件、标准包装，目的国仍为Spain，交期仍未指定。
请先读取最新版本，更新、重新计算并刷新中英待审回复，不重复新建询盘。
保存一个站内待办：2026-11-02 09:00，时区Asia/Shanghai，核对包装与运费。
待办不是实际联系客户，不发邮件、不发送通知。
~~~

日期示例用于2026-11-01演示；之后演示须改成实际未来日期并明确时区。

预期回答要点：询盘ID不变、修订号增加；500×4.80=2400，标准包装附加费0，小计USD2400，不含运税；中英草稿随之更新，待办含上述日期、时间和时区。

展示动作：找到本轮“中英文报价单”卡，依次点“下载中英文PDF”“下载中英文Excel”，打开实际文件。PDF显示500件/标准包装/USD2400及费用范围；Excel有中文和英文两张表，金额一致。使用第二轮卡片，旧卡代表历史快照，不要用旧版本说明当前订单。

## 6 B1 运营生成与下载

可继续原聊天；若另开B聊天，先复制本人回执中的三个ID，明确要求“继续处理这些已有记录，不新建交易”。然后发送：

~~~text
确认采用刚才DESK-001资料包候选事实的第1—6条，保留模拟声明、原始规格与CC0示意图署名。
请按原候选索引真实确认，以AI模式生成英文商品资料、客服FAQ、方图、横图、规格信息图及ZIP下载卡。
基于同一资料包准备Amazon美国站Listing草稿，区分标题、Item Highlights与bullets。
价格、库存、认证、运费、税费、保修和销售授权未知，不能补造或作承诺。
生成文件请使用原生商品资料下载卡，不用通用文件工具重新制作；不发布、不发送。
~~~

如候选不是六条，不机械确认1—6；先核对实际条目再明确确认。

预期回答要点：真实调用确认及生成工具；同一pack_id生成英文文案、FAQ和三图；本机样例FAQ为9条，数量以当前资料结果为准。生成方法显示ai_grounded才算本次AI生成通过；若回退template，说明模型未完成本次生成，不能把它算作AI成功。

展示动作：下载ZIP并打开，查看英文资料、FAQ、三张PNG、事实与来源文件。本例三图尺寸为1200×1200、1600×900、1200×1600；图片是原图/示意图排版。Amazon稿是待审业务稿，不代表已上架。

## 7 B2 问题稿审核

发送：

~~~text
请先检索当前规则知识，审核同一询盘的Alibaba RFQ回复与同一资料包的Amazon US Listing。
为演示错误反馈，将Amazon待审稿的营销句设为：Free shipping, taxes included.
颜色表述暂写gray and white，稍后我会修改。
真实调用trade_review，展示平台规则和报价商务条款两类检查、风险标记与逐条文字批注、规则来源及适用范围。
本轮只审核并展示问题，先不要替我修正或判定批准。
~~~

预期回答要点：工具实际生成审核ID；免费运费/含税与未确认运税范围矛盾，出现高风险及具体片段、原因、建议。平台规则来源与项目商务检查分开标识。若其他问题也命中，应如实展示，不要求硬凑固定总数。

展示动作：在“平台文案审核反馈”展开“反馈一：稿件风险标记”和“反馈二：逐条文字批注”；点开规则来源。可以下载含风险的内部审核报告，下载不等于批准外发。

~~~text
这是修改业务草稿，不改写原始产品事实，不自动重新生成资料包，也不发布。
~~~

预期回答要点：新审核ID关联旧审核；本机已验证运税承诺的2项高风险变为0项，Amazon适用范围与未确定商务条件继续待确认。零命中不代表平台批准、认证或完整法律合规。

## 9 三个辅助亮点

### 企业知识原文判断

提前按[私有知识库指南](PRIVATE_KNOWLEDGE.md)上传仓库示例手册extensions/foreign_trade/demo_knowledge/sample_followup_handbook.md，等待Wiki条目生成完成。聊天选中本人知识库，发送：

~~~text
请查询“外贸样品与跟进知识库（演示）”：KB-PACK-7316每套几件、样品费多少、是否含运费？
客户签收35天后才确认1000套，能否承诺退样品费？分别核对数量与期限两个条件，取手册原文并给出处。
该SKU独立于DESK-001报价，不要套用其他产品政策，不发送消息。
~~~

预期：3件、USD18.50、不含运费；1000套满足至少800套，但35天超过30个自然日，两个条件没有同时满足，不能自动承诺退款。

展示动作：展开回答的原文引用，核对数量与期限条款。必须看到实际Wiki定位和取原文调用；新部署若未上传手册，应先建库，不能复制维护者的库ID或用模型记忆补答案。本次采用Wiki原文追溯，不声称已经配置向量RAG。

### 跨岗位任务与来源变化

发送：

~~~text
读取刚才关联的协同单，展示五岗位六任务、负责人标签、依赖、来源版本与待确认项。
只展示状态，不代替任何岗位验收，不发送通知。
~~~

预期：创建不等于完成；未验收任务保留todo/阻塞。负责人标签不赋予其他账号访问权限，也不表示已启动五个自治智能体。

若演示交接文件下载，操作者应在协同工作台核对每个任务的验收依据、填写负责人和结果、逐项明确人审确认，全部当前版本验收通过后再下载MD/JSON。系统会拒绝未完成验收或来源过期的交接导出。不要为了展示强行“一键全完成”。

可另建独立演练单，改变询盘或资料后展示“来源已变化→相关验收失效→重新核对”；不要改坏已准备好的主演示记录。

### 助手市场复用

1. 能力中心→智能体→添加智能体→创建智能体。填写稳定名称、职责和边界；简介不超过界面上限（当前20字符）。需要工具时选择本人可绑定的外贸插件，不绑定不应共享的私有知识。
2. 用实际反例测试。例如“依据是运税另计，请初审Free shipping, taxes included.并给英文改句”。确认是文字初审还是实际trade_review，不混称。
3. 在助手详情申请上架，选择现有分类、填写摘要与说明。
4. 管理员打开应用中心→用户管理，下方“智能体市场审核”，阅读提示词与绑定能力、填写审核理由后通过。普通成员的“创建与安装智能体”须由管理员显式授权。
5. 安装者进入能力中心→添加智能体→从智能体市场获取，搜索名称并安装。看到本人独立副本后测试一次实际调用。
6. 私有知识和密钥不随副本复制；依赖缺失须由安装者配置。原作者后续修改不会自动覆盖已安装副本。

## 10 异常时如何继续

| 情况 | 现场处理 |
|---|---|
| 发送后模型仍在运行 | 等待本轮，不重复发送；先让评委看已经保存的卡片、来源或文件，避免重复创建 |
| 模型网关超时或续接失败 | 记录失败；先查看工作台是否已有写入。新问题明确“继续处理询盘ID…，先读取最新版本，从未完成步骤继续，不新建、不重放已完成操作” |
| 长聊天接近上下文上限 | 按阶段新建短聊天，明确提供同一询盘/资料包/审核ID；不换商品冒充同一交易 |
| 401或登录失效 | 登录同一公开实例；重启后的内存会话失效不代表业务记录丢失，不重新init |
| 409版本冲突或旧下载失效 | 读取最新记录；业务条件变化才重算，事实变化才重新确认/生成；按新来源版本复审 |
| 422缺少数量、包装或确认 | 补齐真实输入，展示事实并取得明确确认；不让模型暗补参数 |
| 官网/GLEIF暂时不可访问 | 展示未核实和实际失败信息，不把旧资料说成刚抓取，也不伪造买家结论 |
| 独立买家搜索提示未配置 | 本机尚无搜索服务，主线使用用户给定官网核验；该扩展须配置搜索服务后另测 |
| 生成回退本地模板 | 明确不是本次AI生成成功。模型不可用时工作台可显式选本地原文模板，只整理已确认英语事实，不承担翻译 |
| 交接下载被拒绝 | 核对全部任务是否按当前依据完成明确人审；不要绕过来源及验收守卫 |

## 11 现场结束前核对与讲解

- 同一DESK-001、同一询盘，改量前后金额5100→2400可在工具与文件中核对。
- 英文资料、FAQ、三图、ZIP和审核报告能实际打开；保留模拟标识、图片许可与未知条件。
- 至少两类角色/场景：销售RFQ与运营Amazon；至少两类校验：平台规则与报价条款；至少两种反馈：风险标记与文字批注；保留两轮对话和审核关联。
- 能讲清：中文输入→当前账号业务记录/企业原文→模型草稿→确定性规则审核→用户修改→文件交付；错误时保留已存数据并按版本恢复。
- 价值表述以减少重复录入、确定性重算、同事实多处复用为主。没有人工基线、真实发送及成本数据，不报虚构效率提升率、回复率或成交率。
- 商品与报价是模拟数据；图片为原图/示意图排版；规则检查不等于平台批准，外发与发布仍需人工确认。更细的评分项与实测记录见[最终整合验收](FINAL_DEMO_20261101.md)。
