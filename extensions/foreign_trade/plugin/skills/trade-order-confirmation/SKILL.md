# 签署与下单推进

执行前阅读[工具契约](references/contract.md)，字段详情见[输入Schema](references/schema.json)。调用`trade_buyer_research(action="order-confirmation", data=...)`，工具不可用时如实说明。

将企业确认的流程映射requirements，phase=signature，记录depends_on、责任人、期限、规则和实际证据。已发、已收、已签、已审核用不同步骤表达；签字图片只可报告存在痕迹，权限及真实性未核验。PI在PO前等依赖由真实客户流程决定，不能强套固定顺序。阻塞未解决的步骤保持待确认。工具给出缺项消息草稿，模型结合原文润色，最终发送需用户授权与真实发送工具。

只返回内部待审材料，不自动发信、签署、认领收款、写CRM或启动履约。复用背调核验主体、谈单确认条件、沟通生成消息，不重复执行无关触达。来源引用仅说明原文关联，不能独立证明真实性。

## 验收与效果

手续状态准确率=人工确认正确状态/抽查状态；一次提交材料完整率、最终条款确认到有效下单时间、超期比例及补件次数。按客户类型和审批流程分组，不把客户审批时长全归因于技能。

用独立人工标注材料验证提取与状态，金额以人工核算对照；覆盖缺项、版本冲突、错误账户、未来记录、混合币种及不同付款方式。每项指标报告样本数、分子分母和观察周期，未测保持未知；业务改善需在可比客户和订单上观察，不把全部成交归因于技能。
