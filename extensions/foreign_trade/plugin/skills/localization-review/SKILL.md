# 本地化产出、规则校验与反馈

本技能使用本公开项目的 `trade_review` 原生工具，身份由当前认证用户绑定。仅制作内部草稿和审阅记录，不向客户发信，不发布商品，不声称通过法律认证或平台审核。

## 明确场景

- `alibaba_rfq`：销售给具体买家的采购回复。优先回应SKU、数量、包装、目的国、报价范围、生产与运输区别、需买家确认的问题，使用简洁礼貌商务英语；避免泛泛广告文案。
- `amazon_listing`：运营准备Amazon美国站非媒体商品页面。写清产品身份、客观规格、用途和消费者能理解的利益点；区分标题、Item Highlights和要点，不把B2B询盘报价当零售价，不补造库存、认证或经销授权。
- 中文用户输入可以生成英语目标内容；销售与运营是不同角色/场景。西班牙语仅在用户指定且已核对事实时使用，不能声称语言选择自动完成法规适配。

## 必须执行的链路

1. 从 `trade_inquiry(get)` 或 `trade_product_content(get)` 读取实际来源，取得当前ID、revision和事实。RFQ必须有当前计算报价；产品资料须已有确认后的产出。没有来源时先通过对应技能创建和核对，不能编造ID或事实。
2. 调用 `trade_review(action="knowledge", data={"channel":"alibaba_rfq"或"amazon_listing","language":"en"})` 检索当前有效规则，引用返回的版本、范围和官方链接。不要凭记忆使用过期标题上限；如发现规则过期或范围不符，说明待人工核验。
3. 依据来源和规则生成平台/角色适配草稿。草稿字段为 `title`、`body`、`bullets`（数组）、`item_highlights`（独立字段，可空）、`language`（en/es）、`locale`。不能将Item Highlights当成bullet字段合并。货币、数量与金额来自计算工具，未知运费/税费/付款/有效期/贸易术语保留待确认。
4. 完整读取本技能后调用 `trade_review(action="review", data={"source_type":"inquiry"或"content_pack","source_id":实际ID,"source_revision":实际revision,"channel":所选场景,"draft":草稿})`。
5. 只有真实工具回执才代表已校验、已保存。展示草稿、文字批注（原片段/原因/建议）和风险标记、证据来源、待确认事项以及下载卡。`no_issues_detected`只表示已实现规则未发现问题，不等于全面合规。
6. 用户第二轮要求修改时，重新读取来源并核对revision，修正草稿，再调用review，传入上一轮真实 `previous_review_id`。解释已解决、仍存在和新增问题；不得只口头声称已修复，不得覆盖历史审阅。

## 两轮演示示例

第一轮：基于DESK-001模拟询盘生成英语RFQ草稿。若用户要求“免费运费、保证7天到货”，说明来源未支持，保留为待审示例并让校验工具标记风险，不将其作为可发送的正式报价。
第二轮：按批注删去无依据承诺，保留准确小计、运税另议、参考生产时间和明确待确认条件，重新校验并展示前后变化。

Amazon演示：用真实Pi资料或同订单DESK确认事实编写美国站Listing，检索当前标题与Item Highlights规则后校验。用户补充/修改卖点时不得把未知商业条件变成事实。更换source、channel或源版本须重新生成审阅记录，不复用旧结论。

## 失败处理

403为安装/归属/启用问题；409为来源已变或技能尚未完整读取，先按提示刷新或读技能；422为字段或草稿不完整，先补充，不猜值。网络模型失败时保留已保存事实和历史审阅，不自动发送内容。下载只使用工具返回的真实review_id对应入口，陈旧来源应重新审阅。
